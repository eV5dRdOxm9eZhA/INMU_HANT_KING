# HANT_INMU_PLAY（公開版）

Webカメラでポーズを判定して点数を稼ぐ、小田急風のランキングゲーム。
**GitHub Pages**（画面）＋ **Firebase**（アカウント/ランキング、無料のSparkプランで動作）の構成です。
自前のサーバーは不要です。（Cloudflare Workers版も `worker/` に残してあり、設定で切り替えられます）

```
ブラウザ（この端末の中）                          Firebase（Google）
┌───────────────────────────────┐    HTTPS    ┌──────────────────────────────┐
│ カメラ → 骨格推定 → ポーズ判定  │ ─────────▶ │ Authentication: 名前+パスワード │
│ （映像・座標はここで完結）      │  点数だけ   │ Firestore: 名前/点数/最終アクセス │
└───────────────────────────────┘             └──────────────────────────────┘
   画面・AIモデルは自サイト(GitHub Pages)から配信
```

## 1. プライバシー設計（ここでいうプライバシー＝利用者の顔）

| 項目 | 内容 |
|---|---|
| **カメラ映像** | ブラウザ内で判定するだけ。**送信も保存もしない**（通信コードに映像を扱う処理が存在しない） |
| 判定AI | MediaPipe とモデルを**自サイトから配信**。判定中に外部へ通信しない |
| Firebaseに保存するもの | 名前 / 点数 / 最終アクセス時刻 / 認証情報のみ（映像・IP・端末情報・メールは保存しない） |
| パスワード | **ブラウザ内で PBKDF2(15万回) をかけた値だけ**をFirebaseへ渡す。生のパスワードはGoogleにも届かない |
| ログイン用メール | 利用者は入力しない。内部で「名前のハッシュ@hant-inmu.example」という**架空のアドレス**に変換して使う（実在しないのでメールは送られない） |
| 他人のデータ | Firestoreルールで「本人しか書けない」「加点は経過時間×125点/秒+50まで」「ランキング取得は最大10件」に制限 |
| データ削除 | 設定画面から**アカウント削除**（点数も消える）。TTLを設定すれば180日アクセスのないデータは自動削除 |
| パスワード再設定 | **ありません**（忘れたら別の名前で新規登録）。画面にもそう表示しています |

### 正直な限界
- **通信の途中でIPは必ず見えます。** GitHub Pages と Google(Firebase) には、接続した時点でIPが届きます。アプリは保存しませんが、事業者側のログは制御できません。
- **点数は端末側で数える**ため、改造した人は点数を偽れます。ルールで「加点の速さ」に上限を掛けて被害を抑えていますが、完全防止はできません（映像を送らない設計とのトレードオフです）。
- Firestoreの設計上、**名前を指定すれば、その人の点数と最終アクセス時刻は誰でも引けます**（最大10件の一覧しか取れないので全員分のダンプは不可）。名前に個人情報を入れないでください。画面でもそう案内しています。
- 表示名の「なりすまし」は、**改造したクライアントなら**同名で作れます（通常の画面では名前の重複は登録時に弾かれます）。
- ログイン状態はこの端末のブラウザ（IndexedDB）に保存されます。共用PCではログアウトしてください。

## 2. 公開手順（Firebase版）

### A. Firebaseの設定（コンソール: https://console.firebase.google.com/ ）
1. **Authentication → Sign-in method → 「メール/パスワード」を有効化**（「メールリンク」はOFFのまま）。
2. **Firestore Database → データベースを作成**（本番環境モード、ロケーションは `asia-northeast1`(東京) など）。
3. **Firestore → ルール** に `firebase/firestore.rules` の中身を貼り付けて**公開**。
   - 公開前に「ルールプレイグラウンド」で、未ログインの `players/xxx` への書き込みが**拒否**されることを確認してください。
4. （推奨）**Firestore → TTL（有効期限）** で、コレクショングループ `players`、フィールド `expireAt` のポリシーを作成 → 180日アクセスの無いデータが自動削除されます。
5. （**重要・推奨**）APIキーの利用元を絞る: [Google Cloud コンソール](https://console.cloud.google.com/apis/credentials) → 対象プロジェクト → 「ブラウザキー」→ **アプリケーションの制限: HTTPリファラー** に `https://<ユーザー名>.github.io/*` を登録（動作確認用に `http://localhost:*/*` も）。
6. （推奨）**プロジェクトの設定 → 全般** の「公開名」「サポートメール」を、個人名の入らないものにする。

`config.js` にはすでに設定値（`firebaseConfig`）が入っています。これは**公開前提の値**で、秘密ではありません。

### B. 画面（GitHub Pages）
1. 新しいリポジトリを作る（**リポジトリ名・説明に個人名を入れない**）。このフォルダの中身をpush。
2. **Settings → Pages → Source を「GitHub Actions」** にする。
3. `main` にpushすると、自動で テスト → 判定エンジン/モデルの取り込み → 公開 されます（`.github/workflows/pages.yml`）。
4. 公開URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）で動作確認。

> 手元で試す場合: `npm install && npm run vendor && npm run build` → `_site/` を `localhost` かHTTPSで配信（カメラ利用に必須）。

### C. 開発者の個人情報を残さないチェックリスト
- [ ] **push前に** gitの名前とメールを匿名に: `git config user.name "anonymous"` / `git config user.email "<id>+<name>@users.noreply.github.com"`（GitHubの「Keep my email addresses private」もON）。履歴に残ると消せません。
- [ ] リポジトリ名・説明・READMEに本名や所属を書かない
- [ ] Firebaseプロジェクトの名前・ID・公開名・サポートメールに本名を使わない（`projectId` は公開されます）
- [ ] 画像・音声のメタデータは除去済み（EXIF/WAVの制作ソフト情報なし）。差し替えるときも書き出し時に消す
- [ ] 元ファイルにあったLAN内IP(10.x.x.x)・外部画像URLはコードから削除済み

### `firebaseConfig` から作成者（アカウント）はわかるのか
`apiKey / projectId / appId / messagingSenderId` などの値自体には、メールアドレスや名前は含まれていません。これらから**作成者のGoogleアカウントを公開情報として引く方法は一般には提供されていません**。ただし次の点には注意してください。
- `projectId` / `authDomain` は**作成時に付けたプロジェクト名**から作られます。名前に個人名を入れていると、それが見えます。
- 「公開名」「サポートメール」に個人情報を入れると、利用者向けの画面（メールやログイン画面）に出ることがあります。
- Googleは契約上・法的手続きではプロジェクトの所有者を把握できます（一般の第三者には見えません）。
- 不安なら、**このプロジェクト専用のGoogleアカウント**を作ってFirebaseを作成すると、普段のアカウントと切り離せます。

## 3. 素材
- 背景画像（待機用1枚＋曲に合わせて切り替わる6枚）は元の画像を軽量化しただけで、加工（ぼかし）はしていません。`scene1〜5` はMVの場面を使っています。
- 楽曲は作者が改変可としているとのことで、そのまま使用しています。画像（背景2枚）の権利は未確認です。差し替えるときは同じファイル名で `assets/` に置くだけです（`bg-before.webp` / `bg-after.webp` / `detect.mp3`）。
- 「安全設定」の子猫画像は、外部サイトの画像リンクをやめて**自作のイラスト**（`assets/safe-cat.svg`）にしました。
- 動画削除イベントのアイコンは、再生ボタンの形をした汎用のSVGです。

## 4. ゲーム仕様
- **点数**: ポーズ中 +100点/秒、ポーズしていない間は -10点/秒（0点まで）。点数はアカウントに紐づき、次回も続きから。
- **動画削除イベント**: ポーズを**7秒以上**続けていて、今もポーズ中のときだけ起きます（タイミングは毎回ランダム。最初はポーズ7〜16秒後、以降は最短6秒＋ランダム（平均約15秒おき、最大36秒））。画面中央にYouTube風アイコンが**うっすら**現れ、**1.5秒**でだんだんはっきりします。
  - はっきりした瞬間にまだポーズ中 → **-114514点**（赤フラッシュ＋画面揺れ＋**短い警報音**。点数はマイナスになりえます）。
  - その前にポーズをやめる（0.3秒以上）→ アイコンが消えて **「削除回避成功！ もう一度ポーズをしてください！」**。
  - 回避の判定は実際のポーズで行います。ただし、イベント中と終了後の**1秒間**は、点数の加算と曲の再生が途切れないよう「ポーズ中」として扱います。この1秒以内に構え直さないと、ポーズ切れ（曲は最初に戻る）になります。
  - 数値は `js/app.js` の `CFG.del` で調整できます（`afterMs` が終了後の猶予）。`index.html?fast` で開くと短い間隔で試せます（テスト用）。
- **背景は曲の再生位置で切り替わる**: **10秒に1枚**、`SCENES`（`js/app.js`）の順に変わります（クロスフェード）。枚数は自由で、足りなければ先頭から繰り返します。間隔は `SCENE_SEC`。
- **完走ボーナス**: 曲を最後まで流しきる（ポーズを途切れさせずに最後まで）と、**その回の獲得点が2倍**（獲得分をもう一度加算）。続けてポーズしていれば次の回が始まります。サーバー側は、200秒に1回・最大30000点までのボーナス加点だけを許可します（Cloudflare版のみ。Firebase版は加点速度制限で切られます）。既存のD1には、最初の点数送信時に `bonus_ts` 列が自動で追加されます。
- **徳政令カード**: 点数がマイナスのときだけ、画面下に「📜 徳政令カード（マイナスを0に）」ボタンが出ます。押すとマイナスが**ちょうど0点**に戻ります（何度でも使えますが、0より上には増えません）。サーバー側も「マイナス→0」だけを特別に許可します（Cloudflare版のみ・Workerの更新が必要）。
- **軽量モード**: スマホ（タッチ端末）では既定でON。軽い判定モデル（lite）と小さめの映像で動かして、反応を速くします。設定の「軽量モード」で切り替え（次回起動から反映）。PCでも、重いときはONにできます。
- **スマホ**: 横画面を主対象に最適化（縦画面でも崩れませんが横を推奨）。

### 無料枠の目安（Firebase Spark）
点数の保存は15秒ごと、ランキング更新は60秒ごと。1人が1時間遊ぶと 書き込み約240回・読み取り約600回 で、無料枠（書き込み2万/読み取り5万 毎日）では**1日あたり延べ約80時間分**です。超えるとその日はFirestoreが止まります（課金はされません）。

## 5. テスト
```bash
npm install
npm test                          # 判定ロジック(7) + Firebase版クライアント(9) + Cloudflare版サーバー(13)
node --no-warnings tests/e2e.mjs  # 実ブラウザで画面+API通し(21)（要 playwright。MediaPipeとFirebase SDKは偽物に差し替え）
```
- **Firebase版は、実際のFirebaseに接続したテストはできていません。** 偽SDKで「クライアントがルールを通る書き込みだけを行うか」を確認した段階です。`firestore.rules` の文法と動作は、上記の手順3（ルールプレイグラウンド）で必ず確認してください。

## 6. Cloudflare Workers版に切り替える場合（任意）
`worker/` に動作確認済みの実装があります（IPを読まない・点数の加算上限・ログインのロック・自動削除など）。`wrangler d1 create` → `schema.sql` 適用 → `wrangler secret put PEPPER` → `wrangler deploy` のあと、GitHubの Actions 変数 `API_BASE` にWorkerのURLを入れると、デプロイ時に自動でこちらへ切り替わります。`wrangler.toml` の `ALLOWED_ORIGINS` にGitHub Pagesのオリジンを指定してください。
